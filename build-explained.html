Taboola Assignment – Build Explained

A Java 21 / Maven project (com.taboola:assignment:1.0-SNAPSHOT). This page walks through every piece of the build and why it's there.

Project layout

Taboola/
├── pom.xml                      ← build definition (the heart of the build)
├── mvnw / mvnw.cmd              ← Maven Wrapper scripts (Unix / Windows)
├── .mvn/wrapper/
│   └── maven-wrapper.properties ← which Maven version the wrapper downloads
├── src/
│   ├── main/java/com/taboola/assignment/Main.java       ← your code (empty class so far)
│   └── test/java/com/taboola/assignment/SanityTest.java ← one JUnit test
├── target/                      ← generated output (compiled classes, test reports)
└── .github/modernize/…          ← tooling hooks from a Java-upgrade assistant

The build flow

compile src/main→ compile src/test→ run tests (Surefire)→ package assignment-1.0-SNAPSHOT.jar

Run it with .\mvnw.cmd clean test (or package to also create the jar).

pom.xml, section by section

Coordinates groupId / artifactId / version

com.taboola · assignment · 1.0-SNAPSHOT · jar

The unique name of your project. groupId is the organisation, artifactId the project, version the release (-SNAPSHOT means "still in development"). packaging=jar means the output is a .jar file.

Why you need it: Maven refuses to build without it, and it names the output file assignment-1.0-SNAPSHOT.jar.

maven.compiler.release = 21

<properties>

Compile the code as Java 21 and check it only uses the Java 21 API.

Why you need it: Without it Maven falls back to an old default (Java 8), so modern features such as records, var, switch expressions and text blocks wouldn't compile. Your machine must have JDK 21+.

project.build.sourceEncoding = UTF-8

<properties>

Reads source files as UTF-8.

Why you need it: Makes the build behave the same on Windows, Mac and Linux, and avoids garbled non-ASCII characters and warnings.

Dependencies

Both are test scope: used only when running tests, and not shipped in the final jar.

junit-jupiter 6.1.3

org.junit.jupiter:junit-jupiter

The testing framework: gives you @Test, assertEquals, etc. This one artifact bundles the API, the parameterized-test support, and the engine that actually runs the tests.

Why you need it: Lets you write automated tests. SanityTest uses it.

mockito-core 5.24.0

org.mockito:mockito-core

Creates fake ("mock") objects so you can test a class in isolation, e.g. replace a real HTTP client or database with a stub and verify how it was called.

Why you need it: Useful once your Main/service code has collaborators. It isn't used yet, so it's optional today, but is typical for assignments like this.

Build plugins

maven-compiler-plugin 3.15.0

Runs javac: turns src/main/java/**.java into target/classes, and tests into target/test-classes.

Why you need it: It's the step that compiles your code. Pinning the version makes builds reproducible and supports Java 21.

maven-surefire-plugin 3.6.0

Finds and runs the tests, then writes reports to target/surefire-reports.

Why you need it: Old Surefire versions don't detect JUnit 5/6 tests, so tests would silently not run. A recent version is required for JUnit Jupiter.

Maven Wrapper

mvnw, mvnw.cmd, .mvn/wrapper/maven-wrapper.properties

Small scripts that download and use Maven 3.9.9 (the distributionUrl in the properties file) automatically on first run.

Why you need it: You (or a reviewer) don't have to install Maven. Everyone builds with the same Maven version. Use mvnw.cmd on Windows, ./mvnw on Mac/Linux.

Source files

Main.java

src/main/java/com/taboola/assignment/Main.java

An empty class in package com.taboola.assignment. It's the placeholder where the assignment solution goes.

Why you need it: Production code lives in src/main/java; the folder path must match the package name.

SanityTest.java

src/test/java/com/taboola/assignment/SanityTest.java

One test asserting 1 + 1 == 2. It tests none of your code.

Why you need it: It proves the toolchain works (JDK, Maven, JUnit, Surefire). Replace or add real tests as you write the solution.

Generated and tooling folders

target/

Everything Maven produces: compiled .class files, status caches, and test reports. Last run: 1 test run, 0 failures, 0 errors.

Why it exists: It's disposable build output. Never edit it by hand; mvnw clean deletes it and it should be git-ignored.

.github/modernize/java-upgrade/

Hook scripts (recordToolUse.ps1/.sh) left by a Java-upgrade assistant that logs tool usage while upgrading the project.

Why it exists: Not part of the build. You can safely ignore or delete it.

Quick commands

.\mvnw.cmd clean          # delete target/
.\mvnw.cmd compile        # compile main code
.\mvnw.cmd test           # compile + run tests
.\mvnw.cmd package        # test + build target/assignment-1.0-SNAPSHOT.jar
